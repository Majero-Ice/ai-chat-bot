# Настройка Supabase для аутентификации

## Проблема с логином после регистрации

Если вы получаете ошибку "Invalid credentials" при попытке войти после регистрации, это обычно связано с настройками подтверждения email в Supabase.

## Решение 1: Отключить подтверждение email (для разработки)

1. Откройте Supabase Dashboard
2. Перейдите в **Authentication** → **Settings** → **Email Auth**
3. Найдите опцию **"Enable email confirmations"**
4. **Отключите** эту опцию
5. Сохраните изменения

После этого пользователи смогут входить сразу после регистрации без подтверждения email.

## Решение 2: Использовать SERVICE_ROLE_KEY

Если вы используете `SUPABASE_ANON_KEY`, переключитесь на `SUPABASE_SERVICE_ROLE_KEY`:

1. В Supabase Dashboard перейдите в **Settings** → **API**
2. Скопируйте **service_role** ключ (НЕ anon ключ!)
3. Добавьте в `.env`:
   ```
   SUPABASE_SERVICE_ROLE_KEY=your_service_role_key_here
   ```

**Важно:** SERVICE_ROLE_KEY обходит все ограничения безопасности, используйте его только на бэкенде и никогда не публикуйте в клиентском коде!

## Решение 3: Включить автоматическое подтверждение для тестовых пользователей

1. В Supabase Dashboard перейдите в **Authentication** → **Settings** → **Email Auth**
2. Найдите **"Confirm email"** настройку
3. Установите **"Auto Confirm"** для тестовых доменов или всех пользователей

## Проверка настроек

После изменения настроек:
1. Перезапустите сервер
2. Попробуйте зарегистрировать нового пользователя
3. Проверьте логи сервера - там должна быть информация о создании пользователя
4. Попробуйте войти с теми же учетными данными

## Логи для отладки

Сервер теперь логирует детальную информацию:
- При регистрации: ID пользователя, email, статус подтверждения email
- При логине: детальная информация об ошибке, если она возникает

Проверьте консоль сервера для получения дополнительной информации.
